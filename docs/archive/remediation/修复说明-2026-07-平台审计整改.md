## 一、记忆事件质量分魔法值常量化（Q-010）

### 问题描述

`backend/app/main.py` 的 `/memory/events` 接口中，事件质量分通过内联表达式直接计算：

```python
quality=0.9 if len(text) > 8 else 0.5
```

`0.9`、`0.5`、`8` 三个魔法值无任何语义说明，后续维护者无法判断阈值的依据，也无法与 `memory_events.quality` 字段的文档定义对齐。

### 修复方案

在 `main.py` 模块顶部提取为命名常量，并补充语义注释：

```python
# 记忆事件质量分：内容长度超过阈值视为高质量（更可能包含有效语义），
# 否则按低质量处理。阈值为经验值，与 memory_events.quality 字段语义一致。
_QUALITY_HIGH = 0.9
_QUALITY_LOW = 0.5
_QUALITY_THRESHOLD_CHARS = 8
```

调用处改为：

```python
quality=_QUALITY_HIGH if len(text) > _QUALITY_THRESHOLD_CHARS else _QUALITY_LOW
```

### 验证结果

- 后端全量测试：**523 passed, 1 skipped**。
- 实机验证（麒麟 ARM64 设备）：启动 uvicorn 后 `POST /memory/events` 返回 `quality_score: 0.9`，常量已生效。

## 二、Windows 非 ASCII 路径下进程树测试失败（Q-001）

### 问题描述

`backend/app/tests/test_fix_w05.py` 在 Windows 中文路径（如 `宛委枢忆花朝`）下稳定失败，报错“应存在 cmd 壳拉起的 python 孙进程”。

### 根因分析（两层故障叠加）

1. **第一层：批处理文件编码**
   测试动态生成 `.cmd` 壳脚本并内嵌 `sys.executable` 路径。原实现以 UTF-8 写入，但 `cmd.exe` 解析批处理文件时使用**系统 ANSI 代码页（简体中文 Windows 为 GBK）**，嵌入的中文路径被按 GBK 误读而乱码，导致壳脚本根本无法启动 Python 子进程。

2. **第二层：8.3 短路径亦不可用**
   尝试改用 8.3 短路径规避，但该工作区路径中连短文件名（`宛委枢~1`）都包含非 ASCII 字符，此路不通。

3. **附带问题：`tasklist` 输出解码失败**
   `_alive()` 通过 `subprocess.run(..., text=True)` 读取 `tasklist` 输出判断孙进程存活，GBK 控制台输出触发 UnicodeDecodeError，返回 `None` 引发 `TypeError`。

### 修复方案

核心思路：**让批处理文件内容保持纯 ASCII，把非 ASCII 路径改经环境变量传递**。

- `CreateProcessW` 的环境块是 UTF-16 Unicode，不受批处理文件代码页限制；
- 因此通过环境变量 `WW_TEST_PYEXE` 传入 Python 解释器路径，`.cmd` 内只写 `"%WW_TEST_PYEXE%"`（纯 ASCII）：

```python
shim.write_text(
    '@echo off\r\n'
    '"%WW_TEST_PYEXE%" -c "import os,sys,time;open(sys.argv[1],\'w\').write(str(os.getpid()));'
    'time.sleep(60)" "{}"\r\n'.format(pid_file),
    encoding='ascii',
)
rpc = mcp_hub._StdioRpc(str(shim), [], {'WW_TEST_PYEXE': sys.executable}, 5.0)
```

同时 `_alive()` 增加容错：

```python
subprocess.run([...], capture_output=True, text=True, errors='replace', timeout=30)
```

`errors='replace'` 使无法解码的字节被替换而非抛异常。

### 为什么不用 UTF-8 批处理

在审计对照环境（麒麟 Linux 上的仓库副本）中，同类修复采用了“UTF-8 写入 + 直接内嵌解释器路径”的方案。该方案在**英文路径**的 Windows 上可行，但只要路径含中文仍会触发 GBK 误读——UTF-8 写入并不能改变 cmd.exe 按 ANSI 解析批处理的行为。环境变量方案对任意非 ASCII 路径均成立，是更稳妥的做法。

### 验证结果

- 目标测试 `test_fix_w05.py` 在中文路径工作区下通过；
- 后端全量测试：**523 passed, 1 skipped**，无回归。
