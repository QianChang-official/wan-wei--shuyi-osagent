## 4.1 总体判断

产品落地形态明显强于前沿记忆算法深度。当前可验证的已落地部分:本地端侧运行、MemoryCapsule/Policy Gate/FTS5 检索底座、说「记住」生成可查看/可编辑记忆指令、手动梦境归档、API principal + soul_id 隔离、桌面端 API Key 与本地数据库落盘、有限冒烟/性能验证。

## 4.2 打分(2026-08-20 快照)

| 维度 | 分数 | 说明 |
|---|---|---|
| 产品工程可用性 | 6.5/10 | 端侧运行 + 控制台可用 |
| 记忆智能深度 | 3.5/10 | 基础写入/检索可用,但更新/遗忘/安全治理有缺口 |
| SOTA 研究对齐 | 3/10 | 与 MemOS/HippoRAG/Reflexion 级算法有明显距离 |

## 4.3 领先点

不是 HippoRAG、MemOS 或 Reflexion 级算法,而是:

1. **端侧记忆治理** — 数据不出机、本地治理
2. **麒麟桌面集成** — 信创环境适配
3. **明确安全边界** — stub/simulated/规划 不构成可用承诺
4. **可运行控制台** — 不是纯概念

## 4.4 五大缺口(按 ROI 排序)

### 缺口 1:评测与 Trace(最大短板)

检索「快」不等于检索「准」。当前没有公开的知识召回率、冲突处理正确率、偏好提取准确率报告;赛题要求量化指标,而 misleading_memory_rate 与 production_task_success_rate 仍 pending。

### 缺口 2:混合检索

没有真正的 GraphRAG / HippoRAG 级关联记忆。relation_edges 存在但为空、HippoRAG 复现为桩函数、无自动冲突检测或关联检索。

### 缺口 3:工具轨迹 → 经验记忆

有 workflow dry-run、审计、显式记忆指令;但未见零干预工具轨迹自动压缩与三流融合检索证据。

### 缺口 4:冲突与版本链

有 lifecycle、审计与可能的 relation 字段,但未见时间边失效、版本化冲突合并的公开证据。

### 缺口 5:GuardedMemory 安全层

已有 Policy Gate、API Key、owner 隔离与审计边界;但现代 Agent Memory 安全要求在写入和读取路径都加投毒检测、完整性校验、来源信任分级和策略执行(OWASP ASI06 将记忆投毒视为跨会话持久风险)。

## 4.5 已验证 vs 待验收

| 方向 | 状态 | 证据 |
|---|---|---|
| 本地端侧记忆底座 | 已实现 | FastAPI + Vue3 + Electron,本地 memory.db |
| MemoryCapsule / Policy Gate / 审计 | 已实现但需持续加固 | 架构文档认可抽象合理,历史审计指出过严重问题 |
| 「说记住」用户记忆 | 已实现,偏轻量 | 显式用户记忆/指令列表,不等于自动画像学习 |
| 长期记忆检索 | 已实现基础版 | FTS5 p95 0.8072ms(100 次/50 seed/单机),不证明召回质量 |
| 麒麟原生检索适配 | 半实现 | SDK 不可用时回退 FTS5,OCR/硬件需独立验收 |
| 短期/中期记忆流转 | 已合入信号,需验收 | 无 API/数据结构/测试指标公开证据 |
| 梦境归档/反思 | 半实现 | 手动触发,无自动补跑 |
| Workflow Memory/经验沉淀 | 半实现偏弱 | dry-run,不真实执行 |
| 用户/Soul 隔离 | 已实现基础安全隔离 | API principal + soul_id 双匹配 |
